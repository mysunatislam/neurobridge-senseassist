# NeuroBridge SenseAssist — 90-second judge demo

This script is deliberately conservative: it demonstrates engineering behavior without presenting synthetic cases as clinical validation. Record at 1080p, keep the browser zoom at 100%, enable captions, and rehearse once so the benchmark is already loaded.

## Before recording

1. Run the current verification commands in `SUBMISSION_CHECKLIST.md`.
2. Confirm the README, benchmark UI, and `EVALUATION_REPORT.json` show the same freshly generated results.
3. Use only the bundled frozen synthetic cases. Do not show API keys, local paths, private Antigravity state, camera feeds, microphones, notifications, or patient information.
4. Open these destinations in advance: **Live Therapy Room**, **Agent Traces**, **micro1 Benchmarks**, and the repository `traces/` folder.
5. If physical ESP32 hardware was not tested for this build, call the hardware view a simulator and show the firmware source rather than implying a live device connection.

## Shot list and narration

### 0:00–0:08 — Problem and boundary

**Screen:** Dashboard title and persistent research-prototype notice.

**Say:** “NeuroBridge SenseAssist is a research prototype exploring how a typed, seven-stage workflow can personalize speech-practice cues. Today’s demonstration uses synthetic cases; it is not a diagnostic or clinically validated medical device.”

### 0:08–0:20 — Reproducible input

**Screen:** Open **Live Therapy Room** and select a bundled frozen case. Keep the case identifier and synthetic label visible.

**Say:** “I start from a frozen synthetic case so the same input can be replayed and reviewed. Audio and visual values shown here are test fixtures unless I explicitly enable a live sensor.”

### 0:20–0:39 — Execute and inspect the workflow

**Screen:** Click **Execute Live Trial**, then open **Agent Traces** and scroll through the seven stages.

**Say:** “One action runs perception, reasoning, intervention selection, experiment scoring, digital-twin update, a safety boundary check, and progress export. Each stage exposes its input, output, timing, and decision instead of hiding the workflow behind a single answer.”

### 0:39–0:53 — Safety veto

**Screen:** Show the frozen high-fatigue benchmark case and its safety result. Keep **actuation blocked**, the reason, and any therapist-approval requirement visible. Do not start haptics.

**Say:** “Safety has authority over actuation. In this high-fatigue case the deterministic guard vetoes pacing, records the reason, and requires rest or human approval. No caller is allowed to bypass that result.”

### 0:53–1:08 — Honest evaluation

**Screen:** Open **micro1 Benchmarks**, click **Re-Run All 10 Benchmark Cases**, and show the resulting table or canonical report.

**Say:** “The benchmark replays ten frozen synthetic regression cases through the same implementation. These are engineering proxy metrics—not patient outcomes—and the values on screen are read directly from the generated report.”

Do not memorize numbers in this script. Read the current result shown after the run so the narration cannot drift from the submitted evidence.

### 1:08–1:20 — Interoperability and hardware boundary

**Screen:** Briefly show the FHIR-shaped JSON export, then the ESP32 firmware safety clamp/watchdog source or simulator.

**Say:** “The prototype can export an R4-shaped FHIR bundle for integration testing. The wearable path adds an independent intensity clamp, explicit stop packet, disconnect shutdown, and watchdog; this is prototype firmware, not regulatory certification.”

### 1:20–1:30 — Required development traces

**Screen:** Show `traces/TRACE_MANIFEST.json`, then the first few lines of `traces/DEVELOPMENT_TRACE.redacted.jsonl` in the source repository.

**Say:** “The submission includes source code and 1,129 timestamped, redacted Antigravity development events covering instructions, tool activity, feedback, errors, and retries. Source hashes and known gaps are disclosed in the manifest.”

**Final frame:** Repository URL, video URL, and the sentence “Synthetic research prototype — not for diagnosis or treatment.”

## Claims to avoid

- “Clinically proven,” “FDA approved,” “HIPAA compliant,” “WHO compliant,” or “hospital ready.”
- “Real patient,” “live biomarker,” or “device validated” when showing fixtures or simulations.
- “AI diagnosis,” “autonomous clinician,” or any claim that the workflow replaces a speech-language pathologist.
- Percentage improvements unless they were generated by the current canonical evaluator and are explicitly described as frozen synthetic proxy results.
- “Encrypted API-key storage” when browser storage is plaintext.
